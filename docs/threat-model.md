# Threat model: top 10

Scope: the public site, contributor uploads, moderation, takedowns and storage. Assets in scope: contributors' identities and locations, people audible in recordings, rights holders' works, and the integrity of provenance. Every mitigation below is implemented, with tests named where they exist.

| # | Threat | Mitigations |
|---|---|---|
| 1 | **Broken access control.** Reading or editing someone else's unpublished submission, self-publishing, or a moderator approving their own work | Every route must declare its access level (startup fails otherwise). RLS on every table, with service roles lacking BYPASSRLS and owning nothing. The trigger state machine stops owners publishing, moderators editing content, and self-review. Unpublished IDs return 404. Moderator pages 404 for others. Tests: `packages/db/test/db.test.ts`, `apps/api/test/{security,contribution}.test.ts`, `e2e/tests/contribute.spec.ts` |
| 2 | **Malicious upload.** Polyglots, parser exploits against ffmpeg, decompression or duration bombs, SSRF through playlist formats | Magic-byte sniffing (browser and worker). The signed PUT binds the declared size and type; the stored size is re-checked; the worker's download is capped. ffprobe/ffmpeg are forced to the sniffed demuxer with `-format_whitelist` and `-protocol_whitelist file,pipe`, so no network protocols. Real duration is enforced. A hard 10-minute timeout per process. The worker runs in its own container: non-root, read-only root, all capabilities dropped, pid/CPU/memory limits, default seccomp, and on an internal network with no internet. Never in the request path. Tests: `apps/worker/test/{pipeline,ffmpeg}.test.ts` |
| 3 | **Location and identity leakage.** Precise coordinates, or GPS/EXIF/BWF/iXML tags and device IDs in files | Coordinates are snapped in a DB trigger, so the raw value never reaches disk. ~100 m precision only for attested public places. Transcoding keeps only the audio stream, drops all metadata and chapters, and uses bitexact. **Outputs are re-probed, and anything with surviving tags is refused.** Originals are deleted after processing. Tests: `ffmpeg.test.ts` (fixture with GPS/device/title tags), `pipeline.test.ts` |
| 4 | **Unauthorized media access or enumeration** | Two private buckets. Signed GETs (5–15 min, validated config) are issued only for published audio, or for previews to the owner and moderators. Storage keys are random and never returned. IDs are UUIDv4 |
| 5 | **XSS / content injection** | Per-request nonce CSP with `strict-dynamic` and no `unsafe-inline` scripts. All user text, including the agreement, is rendered as text nodes; an ESLint rule bans `dangerouslySetInnerHTML`. Control and bidi-override characters are stripped. `frame-ancestors 'none'`. A test renders hostile markup as inert text |
| 6 | **CSRF** | SameSite=Lax HttpOnly session cookies. API mutations need a same-origin `Origin` and a double-submit token (`__Host-` cookie over HTTPS). Sign-in and sign-out are server actions, with Next's Origin check |
| 7 | **Abuse and DoS.** Scraping, inbox flooding, upload floods, takedown spam | Per-IP and per-account limits backed by Redis. Sign-in: 10 per IP and 3 per address per 15 minutes. Uploads: 20 per account per hour. Takedowns: 5 per IP per hour. A 64 KB JSON body limit, statement timeouts, and a 2,000-pin cap per viewport. CAPTCHA or proof-of-work stay in reserve for signup and upload |
| 8 | **Rights violations and false provenance** | DB constraints forbid incomplete provenance and authentic-labelled audio whose capture date doesn't match its era. Reconstructions need a disclosure and are badged everywhere. Contributors can't mark rights "disputed" themselves. Three contributor confirmations are required, and the agreement version and time are stored. The moderator checklist is required to publish. Takedowns unpublish immediately, with a full record |
| 9 | **Secrets and supply chain** | Secrets only from env or a secret manager; config errors name variables, never values. Exact pins, a 7-day release-age gate, install scripts off by default, `pnpm audit`, dependency review, gitleaks and Dependabot (with a cooldown) in CI. Images pin base versions. ffmpeg comes from the distribution |
| 10 | **Sensitive data in logs and telemetry** | Logs carry no query strings, cookies, IPs, emails or bodies, and signed URLs are redacted (tested). The audit log stores HMAC'd IPs and never claimant or contributor emails (tested). Sentry has every `dataCollection` category off. Emails are plain text with no tracking |

## Residual risks

- Auth.js database sessions store the session token unhashed. A database read compromise would allow session hijacking until expiry. Sessions last 30 days and refresh daily; restrict DB read access.
- ffmpeg is large attack surface. It runs isolated with no network and tight limits; keep the image updated through Dependabot's Docker updates.
- `style-src-attr 'unsafe-inline'` is allowed for framework and map inline styles. Style attributes cannot run script.
- The development basemap (OpenFreeMap) sees visitors' IPs. Production must set a self-hosted `MAP_STYLE_URL`; the map page throws in production without one.
